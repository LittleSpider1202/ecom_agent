## 1. 背景与目标

### 1.1 产品定位

**任务编排 + 执行引擎**

不只是 AI 对话助手，而是一个能够：
- 用自然语言定义任务流程
- 自动编排 Skill 执行序列
- 协调 RPA、AI、人工协作
- 管理任务状态和流转

### 1.2 核心目标

| 目标 | 描述 |
|------|------|
| 提效 | 自动化重复任务，减少人工操作 |
| 编排 | 自然语言定义流程，AI 编排执行 |
| 协作 | 支持管理者-执行者的任务分配和协作 |
| 沉淀 | 任务流程可复用，经验可传承 |

### 1.3 MVP 目标

1. **验证框架**：任务编排 → Skill 执行 → 状态流转 的核心流程跑通
2. **验证场景**：竞品监控场景落地，产生实际价值
3. **验证协作**：管理者-执行者角色模型可用
4. **自用验证**：先服务自己，快速迭代

## 2. 用户画像与场景

### 2.1 角色模型

| 角色 | 职责 | 典型操作 |
|------|------|----------|
| 管理者 | 定义流程、分配任务、全局监控 | 创建任务流程、分配给执行者、查看统计 |
| 执行者 | 跟进任务、触发执行、唤醒流程 | 查看待办、触发检查、确认完成 |

**MVP 场景**：一人多职，同时扮演管理者和执行者，完整感受协作流程。

### 2.2 任务分类

| 类型 | 特点 | 创建方式 | 示例 |
|------|------|----------|------|
| 周期性任务 | 重复执行，固定频率 | 后台管理 + 对话 | 每日退款、每周开票 |
| 临时性任务 | 一次性，按需触发 | 主要对话创建 | 新品分析、商详设计 |

### 2.3 MVP 落地场景：竞品监控

**用户故事**：
> 作为电商卖家，我希望监控竞品的价格变化和上新动态，以便及时调整自己的定价和选品策略。

**场景流程**：
1. 管理者创建「竞品监控」任务，指定监控的商品
2. 执行者触发检查，系统自动抓取竞品数据
3. 系统对比历史数据，识别变化
4. AI 生成分析报告和建议
5. 执行者根据建议决策

| 变化识别 | 对比历史数据，识别价格/上新等变化 |
| 分析报告 | AI 生成变化报告和决策建议 |
| 数据持久化 | 监控数据存储，支持历史查询 |

#### 交互能力
| 功能 | 描述 |
|------|------|
| Web UI | 三栏布局（导航 + 内容 + 任务面板） |

### 3.2 MVP 不做什么

| 不做 | 原因 |
|------|------|
| 定时自动执行 | MVP 先主动触发，验证核心流程 |
| 用户修改编排 | MVP 编排由 AI 生成，不支持用户修改 |
| 多租户/权限 | 自用优先，不需要复杂用户管理 |
| 知识库沉淀 | 后续按需设计 |
| 移动端 | 先验证核心价值 |
| 全场景覆盖 | MVP 只做竞品监控，验证框架 |

### 4.2 核心机制

#### 4.2.1 自然语言编排

**输入**：用户自然语言描述任务流程

**输出**：YAML 格式的流程定义

**示例**：

用户输入：
```
帮我监控这个商品的价格变化：https://item.taobao.com/xxx
每次我触发检查时，抓取最新价格，和上次对比，
有变化就告诉我变化情况和建议。
```

AI 编排输出：
```yaml
任务名称: 竞品价格监控
触发方式: manual  # 手动触发

步骤:
  - skill: 网页.抓取商品信息
    params:
      url: "https://item.taobao.com/xxx"
    output: current_data

  - skill: 数据.获取历史记录
    params:
      商品ID: "${current_data.id}"
    output: history_data

  - skill: 数据.对比变化
    params:
      当前: "${current_data}"
      历史: "${history_data}"
    output: changes

  - skill: 数据.存储
    params:
      数据: "${current_data}"

  - skill: AI.生成分析报告
    params:
      变化: "${changes}"
      历史: "${history_data}"
    output: report
```

#### 4.2.2 任务状态流转

**步骤类型**：

| 类型 | 执行者 | 触发方式 |
|------|--------|----------|
| auto_rpa | 影刀 | 上一步完成自动触发 |
| auto_ai | 大模型 | 上一步完成自动触发 |
| auto_system | 系统 | 上一步完成自动触发 |
| wait_human | 用户 | 人工点击唤醒 |

**任务实例状态**：

| 状态 | 说明 |
|------|------|
| pending | 待执行 |
| running | 执行中 |
| waiting | 等待人工 |
| completed | 已完成 |
| failed | 失败 |

**状态流转**：
```
pending → running → completed
              ↓
           waiting → (人工唤醒) → running
              ↓
           failed
```

#### 4.2.3 中断条件设计

每个步骤可配置**中断条件**，用于处理异常情况：

```yaml
- name: 微信发送
  type: rpa
  skill: 微信.发送文件

  # 中断条件
  interrupt_conditions:
    - condition: "24小时未收到回复"
      action: pause
      notify: "代记账未响应，请人工跟进"

    - condition: "发送失败"
      action: retry
      max_retries: 3
      fallback: pause
```

**中断动作类型**：

| action | 说明 |
|--------|------|
| pause | 暂停流程，等待人工介入 |
| retry | 自动重试 N 次 |
| skip | 跳过当前步骤 |
| abort | 终止整个流程 |

#### 4.2.4 RPA + Agent 协作架构

**核心原则：步骤原子化 + 状态外置**

影刀（RPA）是同步执行的，无法在执行中暂停交给 Agent 处理再恢复。因此采用以下架构：

```
┌─────────────────────────────────────────────────────────────┐
│                    任务调度器（我们的系统）                    │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐   │
│   │                  外部状态存储                         │   │
│   │   · 当前步骤索引                                      │   │
│   │   · 执行上下文（变量、中间结果）                        │   │
│   │   · 任务状态                                         │   │
│   └─────────────────────────────────────────────────────┘   │
│                           ↑↓                                │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐             │
│   │  步骤1   │ →  │  步骤2   │ →  │  步骤3   │ → ...      │
│   │ (RPA)    │    │ (RPA)    │    │ (等待)   │             │
│   └──────────┘    └──────────┘    └──────────┘             │
│        ↓               ↓               ↓                    │
│     保存状态        保存状态        保存状态                  │
│        ↓               ↓               ↓                    │
│    检查中断条件    检查中断条件     检查中断条件               │
└─────────────────────────────────────────────────────────────┘
```

**设计要点**：

| 原则 | 说明 |
|------|------|
| 步骤原子化 | 每个 RPA 步骤独立执行，执行完即结束 |
| 状态外置 | 上下文保存在外部存储（DB），不依赖 RPA 内存 |
| 调度驱动 | 由调度器决定下一步执行什么 |
| 可中断 | 步骤之间可暂停、等待、条件判断 |

**执行流程**：

```
1. 调度器读取流程定义，获取当前步骤
2. 调用影刀执行当前步骤
3. 影刀返回结果 → 保存到状态存储
4. 检查中断条件
   ├─ 触发 → 执行中断动作（暂停/重试/跳过/终止）
   └─ 未触发 → 继续下一步
5. 重复直到流程完成或中断
```

#### 4.2.5 Skill 设计规范

**Skill 定义格式**：
```yaml
skill:
  name: 网页.抓取商品信息
  type: rpa  # rpa / ai / system
  description: 抓取电商平台商品页面信息

  input:
    - name: url
      type: string
      required: true
      description: 商品页面URL

  output:
    - name: id
      type: string
    - name: title
      type: string
    - name: price
      type: number
    - name: images
      type: array

  implementation:
    tool: 影刀
    script: grab_product_info.py
```

**MVP 所需 Skills**（竞品监控场景）：

| Skill | 类型 | 功能 |
|-------|------|------|
| 网页.抓取商品信息 | RPA | 抓取商品价格、标题、图片等 |
| 数据.存储 | System | 保存监控数据 |
| 数据.获取历史记录 | System | 读取历史数据 |
| 数据.对比变化 | System | 对比新旧数据，识别变化 |
| AI.生成分析报告 | AI | 分析变化，生成报告和建议 |

### 4.3 核心流程

#### 4.3.1 创建任务流程（管理者）

```
管理者用自然语言描述任务
        ↓
AI 理解意图，编排 Skill 序列
        ↓
生成 YAML 流程定义
        ↓
持久化存储
        ↓
可分配给执行者
```

#### 4.3.2 执行任务（执行者）

```
执行者触发任务（或定时触发）
        ↓
执行引擎读取 YAML
        ↓
按序调用 Skill
        ↓
遇到 wait_human 步骤 → 暂停，等待人工
        ↓
人工确认/唤醒 → 继续执行
        ↓
任务完成，记录结果
```

#### 4.3.3 竞品监控流程（MVP 场景）

```
1. 管理者创建监控任务
   "监控这个商品的价格：xxx链接"
        ↓
2. AI 编排流程，保存 YAML
        ↓
3. 管理者分配给执行者（或自己执行）
        ↓
4. 执行者在任务面板看到任务
        ↓
5. 执行者点击 [检查变化]
        ↓
6. 系统执行：抓取 → 对比 → 存储 → 生成报告
        ↓
7. 执行者查看报告，做出决策
```

## 5. 评价体系

### 5.1 目标拆解

```
总目标：提升电商运营效率
    │
    ├── 任务自动化率
    │   └── 自动执行步骤数 / 总步骤数
    │
    ├── 任务完成效率
    │   └── 平均任务耗时
    │
    └── 决策支持价值
        └── 基于系统信息做出的决策数
```

### 5.2 衡量指标

#### 框架层面

| 指标 | 目标 | 说明 |
|------|------|------|
| 流程创建成功率 | >90% | 自然语言 → YAML 编排成功 |
| Skill 执行成功率 | >95% | Skill 调用无报错 |
| 任务完成率 | >90% | 任务最终达到 completed 状态 |

#### 场景层面（竞品监控）

| 指标 | 目标 | 说明 |
|------|------|------|
| 数据抓取准确率 | >95% | 价格、标题等信息正确 |
| 变化识别准确率 | 100% | 有变化能识别出，无误报 |
| 报告有效性 | 主观评价 | 报告对决策有参考价值 |

### 5.3 进化指标

| 指标 | 说明 |
|------|------|
| Skill 数量 | 可用 Skill 持续增加 |
| 任务类型覆盖 | 支持的场景持续扩展 |
| 人工介入率 | 需要人工处理异常的比例持续下降 |

## 6. 优化回路

### 6.1 问题回收机制

| 问题类型 | 发现方式 | 记录位置 |
|----------|----------|----------|
| Skill 执行失败 | 执行引擎捕获 | 任务执行日志 |
| 编排不符合预期 | 用户反馈 | 任务备注 |
| 数据不准确 | 用户核实 | 反馈记录 |

### 6.2 问题归因

```
问题发生
    ↓
判断问题类型
    ├── Skill 层问题 → 检查 Skill 实现
    ├── 编排层问题 → 检查 AI 编排逻辑
    ├── 数据层问题 → 检查数据源
    └── 用户操作问题 → 优化引导
```

### 6.3 闭环修复

| 问题类型 | 修复方式 |
|----------|----------|
| Skill Bug | 开发者修复，更新 Skill |
| 编排模式不足 | 优化 AI Prompt，增加示例 |
| 新场景支持 | 开发新 Skill，扩展能力 |

### 7.2 交互原则

| 场景 | 灵活度 | 交互方式 |
|------|--------|----------|
| 添加监控商品 | 低 | 表单（输入链接） |
| 触发检查 | 低 | 按钮 |
| 查看报告 | 低 | 页面/卡片展示 |
| 分析解读 | 高 | 对话 |
| 决策建议 | 高 | 对话 |
| 创建任务流程 | 高 | 对话（自然语言描述） |
| 唤醒等待任务 | 低 | 按钮/上传文件 |

### 7.3 表单区设计

表单区根据当前选择的任务类型动态切换：

| 任务类型 | 表单区内容 |
|----------|-----------|
| 竞品监控 | 商品链接输入、[检查变化] 按钮 |
| 退款处理 | 时间筛选、退款类型、[批量处理] |
| 数据分析 | 时间范围、指标选择、[生成报告] |
| 商详设计 | 无/很少（主要靠对话） |

## 9. 异常与兜底

### 9.1 异常场景

| 场景 | 处理策略 |
|------|----------|
| Skill 执行失败 | 记录错误，任务标记为 failed，通知用户 |
| 网页抓取失败 | 重试 2 次，仍失败则跳过该商品，继续其他 |
| AI 编排失败 | 提示用户换个方式描述，或提供模板 |
| 人工等待超时 | 定期提醒（MVP 可不做） |

### 9.2 兜底机制

| 机制 | 说明 |
|------|------|
| 执行日志 | 完整记录每步执行，便于排查 |
| 人工介入入口 | 任何时候都能查看任务详情，手动处理 |
| 任务重试 | 失败任务可手动重试 |
