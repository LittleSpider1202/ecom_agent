## 1. 背景与市场机会

### 1.1 电商行业三大特征

#### 特征一：链路长

电商业务从产品到消费者，穿透多个环节和系统：

```
产品 → 采购 → 仓储 → 运营 → 客服 → 物流 → 财务
```

每个环节都有各自的系统（电商后台、ERP、物流系统、财务软件、飞书/微信等），一个业务动作往往需要跨多个系统完成。

#### 特征二：协同场景多

链路上的每个环节需要不同角色配合，信息和操作在人与系统之间反复流转。中小卖家一人多职，需要频繁在不同系统间切换。

#### 特征三：重复工作多，且有明确标准

大部分日常操作不需要创造力，有明确的执行要求和 SOP。比如退款处理、开票流程、库存盘点等，规则清晰、步骤固定，但仍需人工逐步执行。

### 1.2 现有方案的盲区

#### 办公协同工具（飞书、钉钉）

解决的是**信息流**：人与人之间的消息、审批、文档协同。

**未解决的是操作流**：当飞书通知你「该开票了」，从飞书表格拿清单 → 登录税务系统 → 开票 → 下载发票 → 回填到 ERP，这些跨系统的实际操作仍然要人手动完成。

#### RPA 工具（影刀）/ 低代码平台（扣子）

本质上是**通用编程平台**，定位是面向所有用户的灵活工具：

- 需要用户理解编程逻辑（流程编排、变量、条件判断）
- 需要自己设计流程、调试运行、处理异常
- 使用门槛高，市场上有能力使用的商家很少

### 1.3 市场机会

现有工具的定位形成了一个空白地带：

| | 信息流（协同） | 操作流（执行） |
|---|---|---|
| 飞书/钉钉 | 已解决 | 未解决 |
| 影刀/扣子 | 不涉及 | 能解决，但门槛高 |
| **我们的机会** | 不涉及 | **针对电商场景封装，开箱即用** |

核心机会：**在通用 RPA 能力之上，做一层电商领域封装**，把跨系统的操作流自动化，让电商卖家不需要编程就能用。

## 2. 目标用户

### 2.1 用户画像

| 维度 | 描述 |
|------|------|
| 角色 | 个人电商卖家 / 小团队负责人 |
| 经营模式 | 多平台运营（淘宝、拼多多、抖音等） |
| 团队规模 | 1-5 人，一人多职 |
| 典型职责 | 同时承担运营、客服、采购、发货等工作 |
| 技术能力 | 无编程能力，不会使用 RPA/低代码工具 |

### 2.2 MVP 目标用户

**首要用户：自己（项目发起人）**

- 个人电商卖家，多平台运营
- 一人多职，时间精力有限
- 希望自动化处理繁琐的跨系统操作
- 期望沉淀经验，为未来团队扩张做准备

**为什么先服务自己？**

- 对需求理解最深刻
- 能快速验证和迭代
- 方案可以更简化（无需考虑多租户、权限等复杂场景）

## 3. 用户痛点与场景

### 3.1 核心痛点

| 痛点类型 | 描述 | 典型场景 |
|----------|------|----------|
| 重复操作 | 大量重复、机械的跨系统操作任务 | 批量处理退款、批量回复客服、批量上架商品 |
| 信息收集 | 需要持续收集和分析外部信息 | 竞品监控、价格追踪、市场调研、数据分析 |
| 经验沉淀 | 经验停留在个人脑中，难以传承 | 新人培训、常见问题处理、决策依据 |

### 3.2 痛点的本质

三大痛点的共同特征：**操作跨多个系统，步骤有明确 SOP，但现有工具无法串联**。

```
痛点根因：
  操作分散在多个系统 → 无法自动化串联 → 只能人工逐步执行
                                          ↓
                                    重复、低效、易出错
```

### 3.3 典型场景详述

#### 场景一：竞品监控（信息收集类）

**现状：**
- 每天手动查看竞品店铺，了解上新、价格变化
- 信息分散，难以形成系统性洞察
- 容易遗漏重要变化

**期望：**
- 自动监控竞品动态
- 汇总关键变化（新品、价格调整、活动策略）
- 提供决策建议

#### 场景二：退款处理（重复操作类）

**现状：**
- 每天有大量退款申请需要处理
- 大部分是简单场景（超时未发货、仅退款等）
- 手动逐条审核耗时

**期望：**
- 自动处理简单退款场景
- 复杂情况提醒人工介入
- 统计处理结果

#### 场景三：开票流程（跨系统联动类）

**现状：**
- 从飞书表格获取开票清单
- 手动整理 Excel
- 发送给代记账，等待开票完成
- 下载发票，回填到电商系统

**期望：**
- 自动整理开票数据
- 自动发送，等待人工确认
- 自动回填系统

#### 场景四：FAQ 维护（经验沉淀类）

**现状：**
- 客服经验停留在个人脑中
- 新人需要长时间学习
- 同样问题反复解答

**期望：**
- 沉淀常见问题和最佳回复
- 能快速检索相关知识
- 持续积累和优化

## 4. 产品定位

### 4.1 产品愿景

**电商卖家的自动化操作助手**

把电商日常的跨系统操作固化为可执行的流程，让卖家选择任务、填写参数、一键执行。

### 4.2 核心价值主张

| 价值 | 描述 |
|------|------|
| 开箱即用 | 预置电商场景流程模板，无需编程 |
| 跨系统联动 | 串联电商后台、飞书、ERP 等多系统操作 |
| 提效 | 自动化重复任务，节省时间精力 |
| 沉淀 | 流程模板可复用，经验可传承 |

### 4.3 产品形态

- **表单驱动**：选择任务类型 → 填参数 → 点击执行（低灵活度场景最优交互）
- **任务管理**：任务可追踪（执行中/等待中/已完成）
- **流程模板**：预置电商常用流程，开箱即用

### 4.4 关于 AI 的定位

**AI 的强项是推理，不是执行 SOP。**

电商日常 90% 是低灵活度场景（步骤固定、规则明确），这类场景下：
- 表单 + 按钮 > 对话式交互（一次点击 > 一段描述）
- Chat 反而降低效率，增加使用门槛

AI 真正有价值的场景是需要**推理判断**的时候（如竞品分析建议、异常订单判断），未来可以作为原子能力（Skill）按需接入，而非作为主交互方式。

## 5. 竞品分析与差异化

### 5.1 竞品定位对比

```
灵活性高 ──────────────────────────── 易用性高

影刀/扣子                            ecom_agent
(通用平台)                           (电商方案)

"给你积木，自己搭"                    "给你成品，直接用"

用户需要：                            用户需要：
 · 理解编程逻辑                        · 选择任务类型
 · 设计流程                            · 填几个参数
 · 调试运行                            · 点击执行
 · 处理异常
```

### 5.2 差异化总结

| 维度 | 飞书/钉钉 | 影刀/扣子 | ecom_agent |
|------|----------|----------|------------|
| 解决的问题 | 人与人协同 | 通用自动化 | 电商操作自动化 |
| 使用门槛 | 低 | 高（需编程思维） | 低（开箱即用） |
| 覆盖范围 | 信息流 | 所有场景 | 电商场景 |
| 跨系统能力 | 弱 | 强 | 强（基于 RPA） |
| 核心壁垒 | 生态 | 平台能力 | 电商 SOP 沉淀 |

### 5.3 我们的核心壁垒

不是技术本身，而是**对电商业务场景的理解和 SOP 沉淀**。

- 底层：影刀提供 RPA 能力（操作系统和浏览器）
- 中间层：我们把电商场景的 SOP 固化为可执行的流程定义
- 用户看到的：选一个任务 → 填参数 → 跑起来

## 6. MVP 范围

### 6.1 做什么

#### 执行框架
- **流程引擎**：YAML 定义流程 → 自动编排执行 → 状态流转
- **任务管理**：创建、执行、追踪、重试
- **跨系统集成**：RPA（影刀）+ 飞书 + 人工确认

#### 落地场景
- 以实际业务需求驱动场景落地
- **首个场景：开票流程**（从飞书表格获取清单 → 整理 Excel → 发送代记账 → 录入发票 → 回填系统），已完成开发验证
- MVP 验证 1-2 个场景，证明框架可行

### 6.2 不做什么

| 不做 | 原因 |
|------|------|
| AI 对话编排 | 低灵活度场景不需要，表单驱动更高效 |
| 全场景覆盖 | MVP 只验证 1-2 个场景，证明框架可行 |
| 多租户/权限 | 自用优先，不需要复杂的用户管理 |
| 移动端 | 先验证核心价值，再扩展端 |
| 可视化流程编辑器 | 用户不需要编辑流程，用现成模板即可 |

### 6.3 关键决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 交互方式 | 表单驱动（非对话式） | 低灵活度场景下效率更高 |
| 流程定义 | 开发者预置（非用户创建） | 开箱即用，降低使用门槛 |
| 任务组织方式 | 按任务类型（非按角色） | 一人多职场景下，按角色划分意义不大 |
| 首个落地场景 | 开票流程（跨系统联动类） | 自用优先，串联飞书+RPA+人工确认，验证框架核心能力 |
| 平台支持 | 多平台通用 | 卖家多平台运营是常态 |

## 附录：竞品监控场景详细描述

### 用户故事

作为一个电商卖家，我希望：
1. 指定要监控的竞品店铺/商品
2. 系统定期检查竞品动态
3. 发现变化时通知我并生成报告
4. 报告包含变化详情和分析建议

### 监控维度

| 维度 | 说明 |
|------|------|
| 新品上架 | 竞品上架了哪些新商品 |
| 价格变化 | 商品价格调整情况 |
| 活动策略 | 促销、满减、优惠券等 |
| 商品变更 | 主图、标题、详情页变化 |

### 输出形式

- **即时通知**：发现重要变化时推送提醒
- **日报/周报**：定期汇总竞品动态
- **趋势分析**：长期跟踪，发现规律
